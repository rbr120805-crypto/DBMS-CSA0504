Requirements Analysis

Functional and non-functional requirements that drive the system design.

⚙️ Functional Requirements

What the system must do

IDRequirementPriority
FR-01Register & manage student profilesHigh
FR-02Create & manage courses, subjects, semestersHigh
FR-03Record exam scores (internal, mid, final)High
FR-04Log daily/weekly study hours per subjectHigh
FR-05Track attendance (present/absent/late)High
FR-06Record lifestyle factors (sleep, stress, job)Medium
FR-07Log extracurricular participationMedium
FR-08Generate per-student performance reportsHigh
FR-09Dashboard: top performers, at-risk, correlationsHigh
FR-10Role-based access (Admin, Faculty, Student)Medium
FR-11Export reports as CSVLow

🛡️ Non-Functional Requirements

Quality attributes the system must meet

IDRequirement
NFR-01Dashboard query response ≤ 2 seconds
NFR-02Support 50+ concurrent users
NFR-03Passwords stored as salted bcrypt hashes
NFR-04Data retained for 5 academic years minimum
NFR-0599.5% uptime during academic sessions

Scope & Technology Stack

What's included, what's not, and the technologies used.

✅ In Scope

  • Student profile management
  • Course & exam record storage
  • Study habits tracking
  • Attendance management
  • Lifestyle factor logging
  • Performance analytics & reports

❌ Out of Scope

  • Real-time proctoring
  • LMS integration
  • Payment / fee management
  • Alumni tracking
  • Mobile app frontend
  • AI-based predictions

🛠️ Technology Stack

Recommended tools and frameworks

🌐 React.js 📊 Chart.js 🎨 Tailwind CSS ⚙️ Node.js (Express) 🐍 Python (Flask) 🗄️ MySQL 8.0 🐘 PostgreSQL 15 🔑 JWT Authentication 🔒 bcrypt Hashing ☁️ AWS RDS
